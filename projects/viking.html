Viking Assistance

Medlemskap, vägassistans & försäkring Mobilutvecklare (Flutter) okt 2025 – sept 2026

Medlemsapp för Viking där användare beställer vägassistans, hanterar medlemskap och familj, följer ärenden i realtid och når kundsupport — med betalningar och försäkringslogik i bakgrunden.

Overview

Viking Assistance är den kundvända appen för Viking-medlemmar i Norden. Appen samlar medlemskap, vägassistans, fordon, betalningar och support i ett flöde som ska fungera lika bra vid kallstart som efter kontobyte på en delad enhet.

Min roll var att vidareutveckla och stabilisera centrala delar av Flutter-kodbasen: affärslogik kring priser och betalningar, användarflöden i plånbok och familjehantering, samt plattformsspecifik funktionalitet för pushnotiser, Intercom och release till App Store och Google Play.

Jag arbetade med betalningsflöden där produkter, rabatter, fakturor och försäkringsperioder kan kombineras på flera sätt. Technical challenges

Progressiv fördjupning — två områden där komplexiteten var särskilt hög.

1. Pushnotiser, Intercom och sessionsäkerhet

Appen tog emot notiser från både Vikings backend och Intercom. På iOS och Android uppstod problem vid kallstart, när Flutter ännu inte var redo, och när Intercom öppnades utan korrekt activity stack på Android. En extra säkerhetsdimension var att notiser kunde levereras efter utloggning — till exempel på en lånad telefon — vilket krävde kontroll mot aktuell användare och organisation innan navigation.

Lösning i korthet:

  • Central koordinator för notistryck, autentisering och livscykel.
  • Exklusiv Intercom-kö för sekventiella SDK-anrop mot delat sessionstillstånd.
  • Native Swift-kö för APNs tills Dart är redo; Kotlin TaskStackBuilder för Intercom på Android.
  • Tillståndsmaskin för väntande notisåtgärder med omvalidering precis före navigation.

Swift: separera mottagning från hantering tills Flutter är redo.

func enqueueOrForward(
  userInfo: [AnyHashable: Any],
  trustedIntercomPush: Bool? = nil
) {
  precondition(Thread.isMainThread)
  let tap = PendingTap(
    userInfo: userInfo,
    trustedIntercomPush: trustedIntercomPush
  )
  if isDartHandlerReady, canDeliver {
    forward(tap)
  } else {
    pending.append(tap)
  }
}

Dart: validera att notisen fortfarande matchar inloggad kontext innan commit.

bool _isVikingCommitStillValid(PendingNotificationAction action) {
  if (action.phase == NotificationActionPhase.cancelled) return false;
  if (_pending?.id != action.id) return false;
  if (_lifecycleReader() != AppLifecycleState.resumed) return false;
  if (action.requiresAuthentication && !_users.isLoggedIn) return false;
  final notification = action.notification;
  return notification is! VikingPushNotification ||
      _notificationMatchesCurrentContext(notification);
}

2. Fragmenterad pris- och betalningslogik

Prisberäkningar hade vuxit ut i flera views, view models och utility-funktioner. Olika delar av appen kunde tillämpa olika regler för rabatter, perioder och historiska betalningar — svårt att felsöka och riskabelt vid vidareutveckling (inklusive AI-assisterad refaktorering där “var sanningen bor” måste vara tydlig).

Lösning i korthet:

  • ProductPriceResolver med explicit prioriteringsordning för priskällor.
  • UI-oberoende PriceBreakdown och PaymentSummary för konsekvent presentation.
  • TemplateVersionResolver för förnyelser kopplade till rätt faktureringsperiod.
  • Enhetstester mot beräkningskärnan utan att bygga hela ViewModels.

Architecture & implementation

Kodbasen följer i huvudsak MVVM i Flutter med tydligare domänlager där affärsregler flyttats närmare testbara modeller och resolvers. Plattformsintegrationer (push, Intercom, PDF) nås via services och method channels med tydliga gränser mot UI.

Domän & presentation

  • Single source of truth för pris via resolver + value objects.
  • Backend-ägda saldon respekteras — klienten räknar inte om auktoritativa belopp.
  • Historiska kvitton filtrerar barnprodukter via betalningsspecifikation, inte dagens familjestatus.

Asynkron koordinering

  • Intercom: exklusiv kö, timeout och generationsbaserad invalidering.
  • Notiser: faser från queued till executing / cancelled.
  • Crashlytics och diagnostik för produktionsincidenter.

Utvecklingsflöde

Jag tog även fram strukturerade Cursor-workflows för testning och release-verifiering: impact-analys av ändringar, regressionsskydd i tester, tydliga grindar vid oklar affärslogik och read-only-checklista inför distribution — utan att automatisera bort manuellt ansvar vid release.

Results & learnings

  • Konsekventare prispresentation i migrerade betalningsflöden, med enklare felsökning och tydligare plats för nya affärsregler.
  • Stabilare notis- och supportupplevelse på iOS och Android, inklusive säkrare beteende vid kontobyte och asynkron navigation.
  • Bättre underlag för kvalitet genom widgettester, Crashlytics och tydligare domängränser som också underlättar AI-assisterad utveckling utan att sprida logik i UI.
